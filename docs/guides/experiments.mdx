---
title: Experiment Tracking
description: Compare eval runs across model versions and catch regressions before they ship.
---

`Experiment` records every suite run locally and lets you compare results across model versions, prompt changes, or time. No cloud, no account — stored as JSONL in `~/.multivon/experiments/`.

## Basic usage

```python
from multivon_eval import EvalSuite, Experiment, Faithfulness, Relevance

suite = EvalSuite("rag-pipeline")
suite.add_cases(cases)
suite.add_evaluators(Faithfulness(), Relevance())

exp = Experiment("rag-pipeline")

# Baseline run
report_v1 = suite.run(model_v1)
run_v1 = exp.record(report_v1, tags={"model": "gpt-4o", "prompt_v": "2"})

# After your prompt or model change
report_v2 = suite.run(model_v2)
run_v2 = exp.record(report_v2, tags={"model": "gpt-4o", "prompt_v": "3"})

# Compare
exp.compare(run_v1, run_v2)
```

## Interpret a comparison

`exp.compare()` prints before/after metrics, coverage counts, confidence
intervals, and approximate significance tests. These records are summaries:
they do not preserve per-case pairing. A higher pass rate with more errors
may reflect missing evidence instead of an improvement.

For a paired comparison, keep the full reports:

```python
diff = report_v1.compare(report_v2)  # baseline, then proposal
print(diff.pass_rate_delta)
```

In PyPI 0.17.0 this pairs cases by input text and uses McNemar's test over completed quality
pairs. Identical input text is not a stable identity for cases whose context
or expected output changed. Keep case definitions fixed and inspect unmatched
cases and coverage. See [statistical limitations](/guides/statistical-rigor).
The development branch uses [case IDs and content digests](/guides/versioned-evidence)
and requires explicit trust for legacy prompt-only comparisons.

## Tags

Tags are free-form key-value pairs — use them to track anything meaningful:

```python
exp.record(report, tags={
    "model": "claude-sonnet-4-6",
    "prompt_v": "5",
    "dataset": "v2",
    "deployed": "false",
})
```

## CLI

```bash
# List all experiments
multivon-eval experiments list

# Show run history
multivon-eval experiments history rag-pipeline

# Compare two runs
multivon-eval experiments compare rag-pipeline a1b2c3d4 e5f6g7h8
```

## Storage

Runs are stored at `~/.multivon/experiments/<name>.jsonl`. Each line is a JSON object with the run summary — not the full case-by-case output. Use `report.save_json()` separately if you want the full results.

```bash
# Override storage location
export MULTIVON_HOME=/your/custom/path
```

## CI/CD integration

Save the full report before a gate can raise, then record it even on gate failure:

```python
import json
import os
from pathlib import Path
from multivon_eval import EvalReport, Experiment

exp = Experiment("prod-eval")
artifact = Path("eval_results.json")
artifact.unlink(missing_ok=True)  # prevent recording an artifact from an older run
try:
    suite.run(model_fn, fail_threshold=0.85, save_json=str(artifact))
finally:
    if artifact.exists():
        exp.record(EvalReport.from_dict(json.loads(artifact.read_text())), tags={
            "git_sha": os.getenv("GITHUB_SHA", "local"),
            "branch": os.getenv("GITHUB_REF_NAME", "local"),
        })
```

The original gate exception still exits nonzero after recording. Upload the
JSON artifact with an `always()` CI step as shown in [CI/CD](/guides/ci-cd).
